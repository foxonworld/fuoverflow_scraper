PRIMARY BUG: AUDIT ANSWER NOT WORKING
────────────────────────────────────

ROOT CAUSE:
-----------
The /api/audit/subjects/{name}/apply and /api/audit/subjects/{name}/smart/apply
endpoints did not validate the `changes` parameter format. 

When the frontend sent full audit result objects as values (instead of just 
answer strings), the code would try to assign the entire dictionary as the 
answer instead of extracting the suggested answer.

Example of what went wrong:
  
  changes = {
      "q001": {"old_ans": "A", "suggested": "C", "stats": {...}},  ← Full object
      "q002": "D"  ← Just string
  }
  
  Result: question.ans = {"old_ans": "A", "suggested": "C", ...}  ← WRONG!
  
  Expected: question.ans = "C"  ← CORRECT!

AFFECTED ENDPOINTS:
  1. POST /api/audit/subjects/{name}/apply
  2. POST /api/audit/subjects/{name}/smart/apply

IMPACT:
  - Answers become dictionaries instead of strings
  - Quiz data becomes corrupted
  - AI Clean and other features fail
  - Data validation breaks
  - Audit answer feature completely broken

FIX APPLIED:
────────────
Updated both endpoints to properly extract answer values:

1. For apply_audit:
   - If value is dict, extract "suggested" field
   - If value is string, use directly
   - Validate result is non-empty string before saving

2. For apply_smart:
   - If value is dict, extract "final_ans" field
   - If value is string, use directly
   - Validate result is non-empty string before saving

CODE CHANGES (routes.py):

@router.post("/api/audit/subjects/{name}/apply")

KNOWN ISSUES

[Minor] CONCURRENT SAVES RACE CONDITION
  Issue: Multiple concurrent saves to same file can lose updates
  Cause: Shared file I/O without optimistic locking
  Impact: Low (rare in normal usage)
  Status: Design limitation of current architecture
  Workaround: BackgroundTasks serialize operations

Note: This is NOT the audit answer bug - that has been fixed.
